# Skill: 1С:Предприятие - разработка и доработка

## Role
Senior 1С-разработчик (платформа 8.3.24+): расширения конфигурации (CFE), внешние обработки/отчёты (EPF/ERF), BSL, HTTP-интеграции, обмен с внешними API, отладка и пакетная автоматизация через Конфигуратор.

## Когда применять
- Доработка/исправление конфигураций 1С, расширения, заимствование объектов, перехват методов.
- Написание и ревью кода BSL (общие модули, модули объектов, модули форм).
- Интеграция 1С с внешними API (маркетплейсы, банки, ЭДО, HTTP-сервисы).
- Сборка/разборка `.epf` / `.erf`, выгрузка/загрузка конфигурации, обновление БД, публикация.
- Не для: чистого веб-фронта и не-BSL кода (см. `skills/frontend.md`, `skills/api-dev.md`).

## Окружение (эта машина)
- Платформы: `C:\Program Files\1cv8\8.3.27.1859`, `8.3.27.1989`, `8.5.1.1343`. Бинарь: `<версия>\bin\1cv8.exe`.
- Есть: `1cv8.exe`, `1cv8c.exe`, `chdbfl.exe`, `dumper.exe`. Нет: `ibcmd`, `oscript`, `java`, `bsl-language-server`, `v8unpack`, `1cedt`.
- Кодировка: файлы `.bsl` и `.xml` выгрузки - UTF-8 (часто с BOM). В PowerShell 5.1 ставь до команд:
  `chcp 65001 | Out-Null; [Console]::OutputEncoding=[System.Text.Encoding]::UTF8`.
  Читай/пиши файлы с `-Encoding UTF8`; для больших файлов предпочитай инструмент `read`.
- Путь к `1cv8.exe` держи в переменной и не хардкодь в скриптах: сначала `$v8 = "$env:V8_PATH\1cv8.exe"`, `V8_PATH` = каталог `bin`.

## Контекст проекта определяй по файлам
- Расширение: `Configuration.xml` в корне выгрузки, свойства `ObjectBelonging=Adopted`, `NamePrefix`, `ConfigurationExtensionPurpose` (`Patch` / `Customization` / `AddOn`), `ConfigurationExtensionCompatibilityMode`, `ScriptVariant` (Russian).
- Обычная конфигурация: `Configuration.xml` без `ConfigurationExtensionPurpose`.
- Стек и версию бери из `ConfigDumpInfo.xml` и манифеста, не по памяти.
- Префикс собственных объектов расширения - обязателен (напр. `SKИМ_`). Новые объекты без префикса - ошибка.

## Пакетный режим Конфигуратора (проверенные ключи)
Шаблон запуска:
```
& "$v8" DESIGNER /F "<база>" /N<Юзер> /P<Пароль> /DisableStartupDialogs /DisableStartupMessages /Out "<лог>" <Ключ> /DumpResult "<рез>"
```
- Всегда добавляй `/DisableStartupDialogs` - иначе зависнет на диалоге. `/N` и `/P` - **без пробела** после ключа.
- Подключение к базе: `/F <каталог>` (файловая), `/S <сервер>/<имя>` (серверная), `/IBName "<имя>"`.
- Коды результата (`/DumpResult`, файл или `$LASTEXITCODE`): `0` успех, `1` ошибка, `101` ошибки проверки.

| Задача | Ключ |
|---|---|
| Выгрузка конфигурации в XML | `/DumpConfigToFiles "<каталог>" [-Extension <имя>] [-AllExtensions] [-update -force] [-listFile <ф>] [-Format Hierarchical\|Plain]` |
| Загрузка XML в конфигурацию | `/LoadConfigFromFiles "<каталог>" [-Extension <имя>] [-listFile <ф>] [-Format ...]` |
| Конфигурация в .cf / из .cf | `/DumpCfg out.cf [-Extension <имя>]` / `/LoadCfg in.cf [-Extension <имя>]` |
| Применить конфигурацию к БД | `/UpdateDBCfg [-Dynamic+|-Dynamic-] [-Extension <имя>] [-AllExtensions] [-WarningsAsErrors]` |
| Проверка модулей (синтаксис) | `/CheckModules -ThinClient -Server -ExternalConnection [-ExtendedModulesCheck] [-Extension <имя>]` |
| Расширенная проверка | `/CheckConfig -ConfigLogIntegrity -IncorrectReferences -ThinClient -Server [-Extension <имя>]` |
| Сборка внешней обработки | `/LoadExternalDataProcessorOrReportFromFiles "<корневой.xml>" "<out.epf>"` |
| Разборка `.epf`/`.erf` | `/DumpExternalDataProcessorOrReportToFiles "<каталог>" "<in.epf>" [-Format Hierarchical]` |
| Создать базу | `CREATEINFOBASE File="<каталог>" [/UseTemplate <файл>]` |
| Запуск в предприятии | `ENTERPRISE /F "<база>" /Execute "<файл.epf>"` или `/URL "e1cib/..."` |

Порядок для правки расширения: `DumpConfigToFiles -Extension <имя>` → правка XML/BSL → `LoadConfigFromFiles -Extension <имя>` → `UpdateDBCfg -Extension <имя>` → `CheckModules/CheckConfig`.
Всегда проверяй `/Out`-лог и код результата; `UpdateDBCfg` без правок иногда возвращает ненулевой код - сверяйся с логом, а не только с кодом.

> Спецификации форматов, DSL, гайды и скрипты: репозиторий `github.com/Nikolay-Shirokov/cc-1c-skills` (MIT). Нужные файлы - `docs/build-spec.md` (пакетный режим Конфигуратора), `docs/cfe-guide.md` + `docs/1c-extension-spec.md` (расширения), `docs/epf-guide.md`, `docs/db-guide.md`. Документацию и ключи сверяй там и в `its.1c.ru`, не выдумывай.
> Репозиторий поддерживает OpenCode напрямую: ветка `port-opencode`, каталог `.opencode/skills/` (или `python scripts/switch.py opencode`). Можно поставить готовый набор навыков 1С, не переписывая вручную.

## Работа с расширениями (CFE)
- Собственные объекты расширения имеют префикс; заимствованные - `ObjectBelonging=Adopted` + `ExtendedConfigurationObject` (UUID оригинала из основной конфигурации).
- Точка входа в свойства - `<Объект>/<Имя>.xml` + `<Объект>/<Имя>/Ext/`. Модули: `ObjectModule.bsl`, `ManagerModule.bsl`, `Forms/<Форма>/Ext/Form/Module.bsl`, `Commands/<Команда>/Ext/CommandModule.bsl`, `Ext/Module.bsl` (общий модуль).
- Перехват методов заимствованного модуля - **только** декораторами, не правкой оригинала:
  - `&Перед("ИмяМетода")` - код до оригинала;
  - `&После("ИмяМетода")` - код после;
  - `&ИзменениеИКонтроль("ИмяМетода")` - копия тела с маркерами `#Вставка` / `#Удаление`.
  - Контекст совпадает с оригиналом: `&НаСервере`, `&НаКлиенте`, `&НаСервереБезКонтекста`.
- Порядок ключей и структура XML критичны для загрузки: не переставляй элементы, не меняй `uuid`, не трогай `InternalInfo`.
- После любого изменения - `/CheckConfig` и `/UpdateDBCfg -Extension <имя>`.

## Стандарты BSL (Стандарт разработки 1С, редакция текущей платформы)
- Имена: процедуры/функции и переменные - `CamelCase`, без подчёркиваний; функция начинается с действия (`ПолучитьЦену`, `ЗаполнитьТЧ`). Параметры - существительные (`Номенклатура`, `Дата`).
- `Экспорт` только там, где реально нужно. `&НаКлиенте` / `&НаСервере` / `&НаСервереБезКонтекста` - осознанно.
- Отступы - табуляцией; комментарии `//` для строк и `/** ... */` (JSDoc-стиль) для экспортных процедур/функций (Назначение, Параметры, Возвращаемое значение).
- Проверка параметров - в начале, с ранним `Возврат` и понятным текстом. Пустой `Попытка/Исключение` запрещён: логируй и/или `ВызватьИсключение`.
- Ошибки пользователю: `СообщениеПользователю` + `ОбщегоНазначения.Сообщить...`, а не `Сообщить()` (в серверном коде тонкого клиента не видно). `Отказ = Истина` в `ОбработкаПроверкиЗаполнения` / `ПередЗаписью`, не `ВызватьИсключение`.
- Запросы: только параметры (`&Имя`), никогда не собирай текст запроса конкатенацией пользовательских данных. `СрезПоследних(Дата, Условие)` - для периодических регистров.
- Работать со временем/ожиданием: `Приостановить(Секунды)` (8.3.21+) в фоновом задании. **Не** делать busy-wait.
- Кириллица vs латиница: следи за символами в идентификаторах (`Истина`/`Ложь`, не `истина`), чтобы не породить разные имена.

## HTTP-интеграции (проверено на живом проекте)
- Всё через `HTTPСоединение` + `HTTPЗапрос`; тело - `УстановитьТелоИзСтроки(Текст, КодировкаТекста.UTF8)`. Таймаут задавай в `Новый HTTPСоединение(Сервер, Порт, Юзер, Пароль, Прокси, Таймаут)`.
- Один тип возврата на функцию. Не смешивай в одной функции `HTTPОтвет` и строку JSON - это ломает вызывающий код.
- Обработка ошибок: проверяй `КодСостояния`; `429` и `5xx` - повтор с нарастающей паузой (экспоненциальный backoff) в **цикле**, а не рекурсией. Счётчик попыток уменьшай один раз на итерацию.
- Логируй запрос/ответ в регистр сведений (событие, тип, тело) - без `Сообщить()` в пользовательский поток.
- Секреты (API-ключи, токены) - в реквизитах-подключениях/константах и защищённом хранилище, не в коде.

## Антипаттерны (из реального ревью - не повторяй)
1. **Busy-wait**: `Пока ТаймерС > ТекущаяДата() Цикл` с пустым телом = 100% CPU и блокировка серверного вызова. Заменяй на `Приостановить()` / фоновое задание.
2. **`Вычислить("Модуль.Метод()")`** для выбора менеджера - компиляция строки, не статически проверяется. Заменяй фабрикой: `ПолучитьМенеджер(Имя)` со `Если ... ИначеЕсли`.
3. **Двойное уменьшение счётчика** лимита (в начале функции и в рекурсивном вызове) - ретраи кончаются вдвое раньше.
4. **Неверные формулы**: `Цена + Цена * (1 + %/100)` вместо `Цена * (1 + %/100)`. Проверяй арифметику на простом примере (1000 + 10% = 1100, не 2100).
5. **Дубли**: проверку на дубликат при записи делай и для нового, и для существующего (`Если СоответствиеЕсть Тогда ...` не должен пропускать `ПередЗаписью`-контроль).
6. **Определение по подстроке имени** (`СтрНайти(Имя, "WB")`) - ломается при переименовании. Используй `Перечисления.*` и предопределённые элементы.
7. **Пустой `ObjectModule.bsl`** у документа - если есть проведение/заполнение, реализуй; иначе удали заготовку.
8. Ручной парсинг дат - используй `XMLСтрока` / `ДатаИзСтроки` по формату API.
9. Дублирование одинаковых подпрограмм в разных общих модулях - выноси в один общий модуль.

## Проверка результата
1. Синтаксис: `/CheckModules -ThinClient -Server -Extension <имя>` (при необходимости `-ExtendedModulesCheck`).
2. Целостность: `/CheckConfig -ConfigLogIntegrity -IncorrectReferences -ThinClient -Server -Extension <имя>`.
3. Применение: `/UpdateDBCfg -Extension <имя>`, смотри лог `/Out`.
4. Функционал: запусти в `ENTERPRISE` (можно `/Execute "<внешняя обработка.epf>"` с набором проверок).
5. Если доступен `bsl-language-server` - прогони `--analyze`; локально он не установлен, ставь только по запросу (сначала `npm view` / релиз на GitHub).

- [ ] Нет busy-wait, `Вычислить`, `Сообщить()` в серверном коде, пустых `Исключение`.
